# Optimizer parameter groups in published and public training recipes

Checked 2026-10-08. This note informs the proposed `hpo/v1` campaign; it does not change the completed architecture campaign or authorize paid training. Code links pin the inspected revisions. Source recipes use different model parameterizations, optimizer update definitions, batches, and token horizons, so their numerical LRs are implementation facts, not transferable Terminus optima.

## What the comparison changes in `hpo/v1`

1. **Represent roles explicitly.** The present [Terminus optimizer](../terminus/optim.py) has shape-scaled Muon groups, tied-embedding AdamW, one Q/K-gain AdamW group, and one AdamW group for *every other vector or scalar*. In the selected stack, the latter includes main norms, Peri output norms, final norm, and the two-coordinate learned value-residual `value_lambda`. Give these distinct **named manifest roles and telemetry**, initially retaining the architecture control's LR, betas, and decay for each. A split with unchanged settings can be checked for one-step and resumed-update equivalence before HPO begins. A separate rate for the tied matrix's lookup and readout use would require a different parameterization, not merely an optimizer-group setting.
2. **Search important rates without a full product grid.** Start with the plan's independent Muon, tied-embedding, shared norm, and Q/K brackets; recheck Muon near its winner after changing the embedding policy. Observe the final norm, Peri output norms, and `value_lambda` separately. Give one a local multiplier branch only if its update-to-weight/function signal or dense-to-QAT behavior identifies sensitivity. For hidden matrices, Q/K/V/O and FFN gate/up/down should retain named logical roles even when they share a physical LR. A different LR within a fused tensor needs a tested slice-aware update and is a new optimizer recipe version.
3. **Compare effective updates, not literal LRs across repositories.** Record optimizer kind, actual parameter-group LR, shape correction, momentum/betas, update frequency, post-normalization RMS, decay product, and update-to-weight or update-to-activation ratio for every role. The public examples use `0.02`, `0.015`, and `4.2e-4` for different Muon variants/horizons; none validates a universal Terminus LR range. A lower long-horizon optimum remains plausible even if `0.012` wins the short proxy.

The source comparison supports a richer role schema and targeted tests. It does not prove that splitting a role improves Terminus loss; that requires matched dense and QAT experiments under a locked campaign.

The opt-in [`build_hpo_optimizer`](../terminus/hpo_optimizer.py) implements the role schema with architecture-control defaults and optional per-role LR overrides. It does not alter the existing architecture-campaign trainer. The new group layout requires fresh HPO checkpoints or a separately tested optimizer-state migration before resuming an archived run.
