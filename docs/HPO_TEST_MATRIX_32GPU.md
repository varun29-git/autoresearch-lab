# Concrete optimizer test matrix for the 1.5B / 32-GPU recipe

**Proposed 2026-10-08. No GPU runs authorized or performed.** This resolves the [optimizer research](OPTIMIZER_TUNING_RESEARCH.md) and [scale-transfer contract](OPTIMIZER_SCALE_TRANSFER_32GPU.md) into a queue. It assumes the selected **25-layer** Peri-LN plus learned value-residual architecture is fixed. If depth is still open, prepend the separate 20/25/30-layer [geometry queue](HYPERPARAMETER_AUTORESEARCH_PLAN.md#exact-first-proxy-queue-if-depth-is-open) and lock its winner before using this matrix. The human sets the paid cap and launches/stops campaigns.

`M` below is **Muon on logical hidden matrices plus auxiliary AdamW**. `A` is **all-AdamW**, including hidden matrices. A rate for M is the **base** Muon rate before `0.2√fan_in`; a rate for A is the **direct** hidden-matrix AdamW rate. They are never compared numerically as if they were the same update. The current HPO role builder handles M; A needs its own behavior-preserving named-group builder and one-step/resume equivalence gate. The current `sqrt_fan_in_ratio` option also has **one global** `muon_fan_in_base`; a true base-matched comparison requires a **per-role base fan-in** (attention and FFN-down fan-ins differ) and checked readout/init math. The HPO runner/manifest, native GPU parity, and 32-rank certification are prerequisites before paid trials.

| --- | --- | ---: |

The large volumes are the price of a *claim* that optimizer choice, width transfer, large-batch behavior, and ternary outcome have each been checked. Branches stop at their budget gates when evidence is decisive; a reduced queue is documented with the claim it leaves unresolved.

## Stage I — find two fully trained optimizer regions at 200M

Every listed new 0.5B screen is a checkpoint of a **2.5B schedule started from initialization**. “+2B” means resume *that same schedule* to its completed decay. The old architecture checkpoint is a quality reference, not a reusable HPO trial unless all source/recipe/data hashes are identical.

| --- | --- | ---: | ---: | ---: |

| **I2 A hidden matrix** | AdamW matrix `{0.0001, 0.0003, 0.001, 0.003}`; auxiliary rates as above | **4** | Provisional best and its stable lower/higher neighbors, **three** +2B continuations | **8B** |
| **I3 tied embedding, each arm** | `{0.0003, 0.001, 0.003, 0.01}`; the `0.003` trial with that arm's selected matrix rate is reused; keep norm/QK low | **3 per arm** | Best new point per arm only if it beats incumbent: +2B | **3–7B** across arms |
| **I4 matrix recheck after embedding, each arm** | `{η/2, η, 2η}` around that arm's winner; reuse `η`. Invoke when I3 changes embedding policy or exposes a matrix–embedding interaction. | **2 per arm** if invoked | Best new point if it beats incumbent: +2B per arm | **0–6B** |
| **I5 shared main/Peri/final norm, each arm** | `{0.0001, 0.0002, 0.0004, 0.0008}`; reuse `0.0002`; keep tied embedding and Q/K fixed | **3 per arm** | Best new point per arm if better: +2B | **3–7B** |
| **I6 Q/K gains, each arm** | `{0.00005, 0.0001, 0.0002, 0.0004}`; reuse `0.0001`; keep other roles fixed | **3 per arm** | Best new point per arm if better: +2B | **3–7B** |
| **I7 hidden-matrix WD, each arm** | `{0, 0.03, 0.1, 0.3}`; reuse `0.1`, hold embedding WD `0.1`, norms/gains WD `0` | **3 per arm** | Best new point per arm if better: +2B | **3–7B** |

**Fixed first gate:** I1+I2 = **eight 0.5B screens plus six 2B continuations = 16B proxy tokens**, if the provisional best in each arm has stable neighbors on both sides. If I3–I7 all run, their additional screens use **12B**, plus **2B** if the I4 recheck is invoked; completing every newly better row adds at most **20B**, for **28–50B** through Stage I under the stated reuse and triggers. Exact costs shrink when a control wins and expand for near ties, boundary expansions, repeated seeds, or failures that require diagnosis. An LR bracket is accepted only with an interior completed-decay region; if `0.012` Muon or `0.003` AdamW wins at the high edge, preprice an expansion (Muon `0.024` or AdamW `0.006`) behind a numerical safety gate. These are *proposed test points*, not validated safe rates.

**Group improvement gate, after I1–I7:** label fused physical roles `attn_qkv`, `attn_o`, `ffn_gate_up`, `ffn_down`. For each optimizer, test a `0.5×` and `2×` multiplier on **one role at a time**, around its tuned arm-specific matrix incumbent: up to **16 new 0.5B screens = 8B**. Continue at most two promising variants per arm to 2.5B (+**8B** if four promote), then test one combined recipe and one ablation only if independent gains interact. This is a conditional **0–16B** menu. Splitting Q/K/V or gate/up *within* a fused physical weight requires separately tested slice-aware optimizer math and a new recipe version. Open Peri/final norm or value-residual depth bands only if layer diagnostics identify a repeatable pattern; do not tune 25 independent layer rates.

**Other optimizer settings:** after the LR/WD region, test Muon momentum `{0.90,0.95,0.98}` (two new 0.5B screens, then a full continuation only for a better point). On A and M's auxiliary groups, compare `(β1,β2)=(0.9,0.95)` against `(0.9,0.99)` and epsilon `1e-10` against `1e-8` **one axis at a time**, only if update-noise or `√v̂/ε` telemetry warrants it. Repeat a winning LR perturbation with `WD_new = WD_old × LR_old/LR_new` when needed to separate rate benefit from changed cumulative shrinkage. Each such branch gets its own 0.5B safety checkpoint and completed 2.5B rank; it is not included in the Stage I total.

## Stage II — test width transfer at the **same batch and horizon**

Keep **393,216 tokens/update**, the same multilingual manifest, 2.5B-token schedule, depth, context, and architecture. `η_M` and `η_A` mean each arm's Stage-I winning matrix rate. For A, compare the current standard-parameterization control with a fully specified tied-readout/hidden-matrix µP arm predicting hidden `η_A × fan_in(768)/fan_in(d)`; for M, compare current `sqrt_fan_in` against an explicitly specified `sqrt_fan_in_ratio`/tied-readout arm. Both start from a matched base-width function and fresh model initialization. Log the physical LR and cumulative decay for every group.

| Width | Matrix-rate/parameterization runs | Embedding check | Dense tokens if all stated runs finish |
| --- | --- | --- | ---: |
| **700M**, d1536 | Per optimizer: current width rule at `{0.5η, η, 2η}` **plus** the alternate width rule/complete parameterization at `η`. **8 runs total** for M+A. If the alternate center wins, its neighbors are a separately priced expansion. | Per optimizer under its leading width rule: tied-embedding `{0.5×, 2×}` around transferred rate, with center reused. **4 extra runs**. | **12 × 2.5B = 30B** |
| **1.5B**, d2304 | Per optimizer: leading width rule at transferred `η` and its nearest viable neighbor. **4 runs total**. | Per optimizer: one nearest embedding neighbor if the 700M bracket shifted or tied-logit diagnostics drift. **0–2 runs**. | **10–15B** |

At 700M and 1.5B the **0.5B checkpoint is diagnostic only**; the 2.5B run includes it, so do not add those tokens twice. Promote a width rule when its absolute held-out quality is competitive, activation/logit and post-update scales are controlled, and its near-optimal LR region overlaps the proxy prediction. A reversed LR ordering or boundary winner triggers local recalibration; no µTransfer claim is made. The 1.5B narrow check is a *pilot* at the proxy batch, not a production-batch or trillion-token verdict.

## Stage III — choose the 32-GPU **global batch** and its LR

Thirty-two pure data-parallel GPUs can keep 393,216 tokens/update with `3 sequences/GPU × 1 accumulation`. The older throughput target is **2,097,152 tokens/update** with `8 × 2`; it is **5.33×** larger, so it receives its own complete-horizon comparison. If the 32 GPUs include tensor/pipeline parallelism, replace 32 with the data-parallel degree in the batch arithmetic. Use the Stage-II leading width/optimizer rule and a **new 10B-token WSD schedule from initialization** for every row below. Lock this schedule for the batch comparison, for example **0.5B warmup / 7.5B stable / 2B decay / final fraction 0.1**; a 0.5B checkpoint is only a safety check at the warmup peak. This horizon requires a fresh multilingual manifest; no 2.5B schedule is silently extended.

| 200M batch study, separately for M and A | Matrix LR candidates | Updates at 10B | Runs / training tokens |
| --- | --- | ---: | ---: |
| Small-batch control `B=393,216` | `{0.5η, η, 2η}` for that arm | ~25,431 | 3 × 10B per arm |
| Proposed large batch `B=2,097,152` | `{0.5η, η, 2η}` for that arm, auxiliary group rates initially held; recheck embedding if diagnostic drift | ~4,768 | 3 × 10B per arm |
| Middle batch `B=1,048,576` | Center `η`, then nearest LR neighbor | ~9,537 | **Conditional**: 1–2 × 10B per arm if 2.1M loses quality, an edge wins, or the cost/quality frontier is unbracketed |

**Core batch gate:** 6 runs per surviving arm × 10B = **60B proxy tokens per arm**, or **120B if both remain**; each batch gets its own completed LR bracket. A 0.5B prefix at 2.1M contains only ~238 updates, so every quality-ranked batch row completes 10B. Hold WD fixed for the first LR/batch comparison, but record cumulative shrinkage and test one **equal-shrinkage-per-token counterfactual** before rejecting a large batch on a close loss: for equal schedule shapes, the proposed large-batch WD factor is `(B_large/B_small) × (η_small/η_large)` on the affected role. This factor is a diagnostic, not a recommended WD. A promising batch then gets a local hidden-matrix WD bracket `{0.03,0.1,0.3}` on a completed horizon; norm/QK WD stays zero and tied-embedding WD is checked separately if it drifts. Each additional 10B branch is priced separately. Search the fastest fitting microbatch/accumulation decomposition **at a fixed global batch** separately from statistical batch tuning. Compare equal-token and measured GPU-hour Pareto frontiers. Before target production, verify at least the winning batch/LR and a neighboring rate at **1.5B on the actual 32-GPU topology**, each on a complete **10B** schedule: up to **4 × 10B = 40B target-width dense tokens** if both optimizer arms survive. A dominated arm can be archived after a matched completed comparison; an unresolved near tie gets another seed.

## Lock and stop rules

1. **Preserve comparable trials.** Every row has an immutable source/config/data/eval/parameterization hash and append-only receipt. Change one named factor at a time; if the manifest or optimizer math changes, create a new campaign version. The selected stack must be committed into the HPO source before runs; the current planning branch alone is not the selected model implementation.
2. **Numerical gate first.** CPU exact one-step/resume tests, native BF16/FP8 parity, 1/10/100-update coordinate and logit checks at 200M/700M/1.5B, 32-rank gradient and full-logical-Muon equivalence, memory, all-in throughput, and multi-rank resume. Stop a trial on nonfinite loss, broken FP8 scaling, or persistent functional collapse; retain its receipt. No paid sweep begins before the owner-run native gate passes.
3. **Promote only completed evidence.** An early checkpoint can reject gross failures; a close winner needs completed decay, a stable interior LR bracket, domain/task checks, and a second seed if uncertainty could change the decision. A width, batch, or horizon failure reopens only its local neighborhood. Log per-role actual LR, momentum/betas, epsilon, WD, cumulative shrinkage, pre/post Muon update norms, tied-logit effects, gain/λ trajectories, and QAT shock.
4. **Price before launching.** Stage I's specified global/auxiliary/WD queue is **28–50B proxy tokens**, Stage II **40–45B** across widths, Stage III **60B proxy tokens per surviving optimizer arm** plus up to **40B target dense tokens** if both survive, before conditional matrix-role, momentum/beta, longer-horizon, schedule, repeats, and QAT gates. These volumes are a **proposed research budget envelope**, not authorized GPU spending. Native all-in throughput determines GPU-hours and the human's funding decision. A reduced queue must explicitly state which transfer or optimizer-quality claim it no longer resolves.
