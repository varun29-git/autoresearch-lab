# Trial E9 — batched Muon Newton-Schulz and foreach Adam (pre-GPU)

- Trial ID: `e9-batched-muon`; candidate commit on branch `speed/trial-e9-batched-muon` (parent: incumbent instrumented reference).
- Hypothesis: the reference optimizer step runs 175 per-slice `muon_update` calls (~2,600 small Newton-Schulz GEMMs) plus ~1,400 tiny Adam kernels through a serial Python loop once per update. At the locked 524,288-token dense update this per-update serial section is a meaningful fraction of the ~15 s reference update; batching same-shape logical slices into `bmm` and collapsing Adam/momentum pointwise into `_foreach` launches recovers most of it without touching per-update microstep time.
- Changed component: `terminus/logical_muon.py` only. Same pinned NS5 coefficients/steps, per-matrix normalization (`dim=(-2,-1)`), per-shape orientation rule, per-group lr/wd/momentum; identical optimizer state schema (`momentum_buffer`, `exp_avg`, `exp_avg_sq`, `step` per parameter). Class **E**: only launch structure and GEMM batching change; bmm-vs-mm reduction order may shift BF16 roundings.
- Expected whole-update gain: estimate after S0 attribution; Amdahl ceiling = optimizer's exposed share of the update. Reference-loop NS FLOPs ≈ 400 TFLOP BF16/update at very low small-GEMM efficiency; batched service time target ≈ 0.8–1.2 s, so expected saving is roughly (measured optimizer time) − 1 s.
- Correctness checks (done, CPU): bitwise parity of momentum buffers and Adam state vs reference loop; final weights bitwise equal to archived separate-matrix Muon on the fused-slice fixture; 3-update drift within 1e-3/1e-5 (observed bitwise on CPU). Native gate before any speed claim: one paired update from identical state, per-parameter update deltas within the class-E envelope, then paired full-update blocks.
- Memory: transient stacked NS buffers ≈ 5–6 GB over baseline peak, freed per shape group; must stay inside the 74 GB screen envelope at the chosen microbatch.
- Disconfirming signal: optimizer share of traced update time is small (<5%), or batched NS hits occupancy/spill regressions that erase the launch savings.
